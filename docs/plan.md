# 第二版規劃：會說、會用、會進步的學習秘書

本文件是第一版（文字管線）之後的完整規劃，經作者逐項確認。實作時依第 20 節的階段進行，每個階段結束都要能跑、能測（`cargo test`），並更新 `docs/roadmap.md`。若實作中需要改變這裡的決定，先更新本文件。

## 0. 目標與原則

**終極目標**：能和其他國家的高中生、大學生自然聊天。所有選題、對話情境、難度設計都以此為依據。

**出發點（作者的現況）**：

| | 英文 | 日文 |
| --- | --- | --- |
| 程度 | B1–B2 之間，聽力強 | N5 上下 |
| 問題 | 認得很多字，但**不會用**（輸出不足） | 基本文法還沒掌握，**不敢講** |
| 方向 | 逼自己把已知的字說出來、寫出來 | 用短句型開口，降低壓力，累積時數 |

**原則**：

1. **以輸出為主**：主動練習（說、寫、答題）的積分權重遠高於被動接收（聽、讀）。
2. **用自己的資料**：複習與課程素材來自使用者自己的單字表、文法、拍照、關注的主題；資料放在自己的 private repo。
3. **不做登入系統**：信任關係靠 git 的存取權限；任何人都能用公開程式碼建立自己的家庭與學習群組（沒有中央伺服器、沒有固定的總管理員）。
4. **每個人用自己的 Claude**：訂閱帳號是個人的，同一台電腦上也要分開。
5. **練習要有完成感**：對話有回合上限，完成就結束，不開放無限聊天；每個單元通過就得分。
6. **介面一致**：沿用 PaperComposer 的視覺語言與元件（色彩 token、圖示、分頁式設定視窗、左導覽＋中紙張＋右助手）。

## 1. 名詞

| 名詞 | 意思 |
| --- | --- |
| 工作區 | 一個 private repo（例如 `JELearner-private`），可以有多位使用者 |
| 使用者 | 工作區裡的一個人（`profiles/<id>/`），選名字即可進入，不用密碼 |
| 管理員 | 工作區或學習群組的管理者；誰建立誰就是管理員，可以指定其他管理員 |
| 家庭成員 | 沒有 GitHub、使用某個管理員工作區的使用者 |
| 好友 | 有自己 GitHub 與工作區的人，透過學習群組互相看到進度 |
| 學習群組 | 另一個 private repo，只放成員的進度摘要 |
| 教材難度 | 給你什麼內容；快速調整，可升可降 |
| 等級 | 你達到的程度；綜合評估後才升，只升不降 |
| 單元 | 一段可完成、可判斷通過與否的主動練習（一段對話、一組題目） |

## 2. 使用者與工作區結構

### 2.1 工作區新結構

```
JELearner-private/
  workspace.toml           工作區 id、名稱、管理員、成員清單
  sources.toml             共用新聞來源
  topics.toml              通識主題清單（第 7 節）
  recipes/                 共用課程配方（可選，第 13 節）
  profiles/
    <id>/
      profile.toml         名字、頭像顏色、學習語言、各語言程度與難度分數、每日目標、對話設定、週報信箱
      interests.csv        興趣關鍵字與權重（第 14 節）
      vocab/ grammar/      自己的單字表、文法
      materials/           每週素材
      photos/              拍照素材（可選，第 13.3 節）
      lessons/en|ja/       產生的教材
      conversations/en|ja/ 對話紀錄（每段一個檔案）
      records/
        points/YYYY-MM-DD.csv   積分紀錄（每天一個檔案，避免多台電腦衝突）
        progress.csv            複習進度
        mistakes.csv            錯題
      recipes/             個人課程配方
```

`workspace.toml` 範例：

```toml
id = "ws-…"
name = "ellrin 的工作區"
admins = ["ellrin"]

[[member]]
id = "ellrin"
name = "Ellrin"
kind = "owner"              # owner | household

[[member]]
id = "daidai"
name = "daidai"
kind = "household"
devices = ["daidai-macbook"]   # 已核准的 deploy key 名稱（第 16.2 節）
```

### 2.2 從第一版結構搬家

第一版把 vocab、grammar 等放在工作區最上層。App 偵測到舊結構時：

1. 說明要搬到 `profiles/<id>/`，徵求同意。
2. 用 `git mv`（不是 git repo 時用一般搬移）保留歷史，不刪任何檔案。
3. 搬完重新讀入資料庫。

作者的 `JELearner-private` 目前只有範本示範資料，搬家沒有風險。

### 2.3 資料庫

每個「工作區 id＋使用者 id」一個 SQLite：`<config dir>/JELearner/data/<工作區 id>/<使用者 id>/learner.sqlite`。切換使用者時換資料庫，不會混到別人的資料。

## 3. 起始流程與設定

### 3.1 三層設定

| 層級 | 位置 | 內容 |
| --- | --- | --- |
| 這台電腦 | `<config dir>/JELearner/config.toml`（不進任何 repo） | 工作區位置、**這台電腦目前的使用者**、各使用者的引擎選擇、模型、外觀 |
| 使用者 | `profiles/<id>/profile.toml` | 學習語言、程度、難度分數、每日目標、對話設定、興趣主題比例、週報信箱 |
| 工作區 | `workspace.toml`、`sources.toml`、`topics.toml` | id、成員、管理員、共用來源、通識主題 |

`profile.toml` 範例：

```toml
id = "ellrin"
name = "Ellrin"
color = "#ff6b35"
languages = ["en", "ja"]
native_language = "zh-TW"
daily_minutes = 30
report_email = ""            # 可留空

[lang.en]
level = "B1-3"               # 等級（只升不降）
difficulty = 255             # 教材難度分數（內部用，第 5 節）
early_feedback_left = 5      # 還要詢問幾次難度

[lang.ja]
level = "N5-1"
difficulty = 12
early_feedback_left = 5

[conversation]
seconds_per_turn = 15
turns = 20
interest_ratio = 0.6         # 興趣主題比例，其餘為通識
```

### 3.2 起始流程（第一次開啟，或新增使用者）

沿用設定視窗的分頁精靈樣式，每一步都有「上一步／略過／下一步」：

1. **歡迎**：一句話說明 JELearner 與私人工作區。
2. **工作區**：開啟資料夾／建立新的／從 repo 下載（第一版已有）；家庭成員在自己的電腦上選「加入家庭工作區」（第 16.2 節）。
3. **使用者**：列出工作區成員（頭像＋名字），點自己就進入；或「新增使用者」（名字、頭像顏色）。
4. **學習語言**：英文、日文可以都勾。每種語言**自評大級**（英文 A1–C2、日文 N5–N1，各附一句能力描述幫助判斷）、每日目標分鐘數。
5. **Claude 連線**：這位使用者自己的訂閱登入或 API key（第 4 節）。
6. **興趣**：點選常見主題、自己輸入關鍵字；調整興趣與通識的比例。
7. **完成** → 「今日」。

之後都能在設定裡改。

### 3.3 畫面變化

- **頂列左側**：使用者頭像；點開可以切換使用者、新增使用者、開啟個人設定。
- **語言切換**：只顯示這位使用者選的語言；只選一種就不顯示切換。
- **設定視窗分頁**：01 工作區與同步、02 使用者、03 學習語言、04 Claude、05 本機模型、06 學習群組、外觀。

## 4. 每位使用者自己的 Claude

訂閱帳號是個人的，不能共用；同一台電腦也要分開。

- **訂閱**：每位使用者有自己的 Claude Code 設定資料夾 `<config dir>/JELearner/claude/<工作區 id>/<使用者 id>/`，呼叫 Claude Code 時以環境變數 `CLAUDE_CONFIG_DIR` 指定。「用瀏覽器登入」登入的是這位使用者自己的帳號。
  - 已確認 Claude Code 支援 `CLAUDE_CONFIG_DIR`，會把設定寫進指定資料夾。
  - **要再移除 `CLAUDE_CODE_OAUTH_TOKEN`**：這個環境變數會讓 Claude Code 直接使用某個登入 token，不看設定資料夾；不移除的話可能用到別人的登入。
  - **需要在 Mac 實測**：macOS 上 Claude Code 把憑證存在鑰匙圈，要確認不同設定資料夾的登入在鑰匙圈裡也是分開的。若不是，改用其他隔離方式（例如每位使用者一個 macOS 帳號），並在介面上說明。
- **API key**：系統金鑰圈裡每位使用者各存一筆（帳號名稱含使用者 id）；沒有金鑰圈時存在 `<config dir>/JELearner/credentials/<使用者 id>.toml`。
- **防呆**：切換使用者時，若這位使用者沒有自己的 Claude 連線，提示登入或設定，**絕不沿用其他使用者的連線**。

## 5. 難度系統

### 5.1 教材難度與等級分開

| | 教材難度 | 等級 |
| --- | --- | --- |
| 用途 | 決定文章、對話、題目的難度 | 成就、好友排行、升級 |
| 變動 | 快速微調，可升可降 | 只升不降，綜合評估（第 9 節） |
| 依據 | 近期正確率、前幾課的難度回饋、跳級機制 | 積分、技能平衡、近期表現、檢核 |

### 5.2 細分等級

內部用**難度分數**，每個大級 100 分；畫面顯示「大級-小階」。

| 語言 | 大級 | 小階 |
| --- | --- | --- |
| 英文 | A1、A2、B1、B2、C1、C2（分數 0–600） | 每級 4 小階，例如 B1-3 |
| 日文 | N5、N4、N3、N2、N1（分數 0–500） | 每級 4 小階；N5 分 6 小階（剛起步時更常感覺到進步） |

設定時只自評大級，難度分數從該大級的起點開始。

### 5.3 難度怎麼對應到內容

- **英文**：用帶 CEFR 標記的單字表（例如牛津 3000／5000，**有版權，由使用者自行匯入私人 repo**，不放進公開 repo）計算文章中高於目前難度的字所佔比例；文法依 CEFR 文法描述。
- **日文**：依 JLPT 各級文法點與單字（使用者匯入或模型判斷）；小階對應「該級文法點掌握了多少」。N5–N4 預設附假名標音。
- **文章改寫**：新聞先由模型改寫成目標難度（分級讀本式），再用單字表檢查；超出難度的句子替換或刪除。
- **對話**：system prompt 帶入目前難度（大級、小階、可用的文法範圍）。

### 5.4 難度調整

- **前 5 課**：每課結束問「太簡單／剛好／太難」，分別調整 +15／0／−15 分（數值可設定）。
- **之後**：依近期正確率自動微調（例如平均 >90% 往上、<65% 往下，每次 ±5 分）。
- 難度可升可降，但不影響等級。

## 6. 跳級機制

### 6.1 觸發條件（任一成立，數值可設定）

- 最近 5 次課程或對話中，有 3 次回答「太簡單」。
- 連續數個單元正確率 95% 以上，且完成時間明顯短於預期。

### 6.2 第一步：題材是否太單一

檢查最近的課程與對話：

- **主題分布**：是否超過一半集中在同一個主題。
- **單字重疊**：新教材中，複習紀錄裡已經很穩的字佔多少。
- **文法重複**：是否一直出現同幾個文法點。

若太集中：**先換主題、不升難度**。接下來幾課維持同樣難度，換成其他主題（優先通識），確認「簡單」是不是只因為主題熟悉。

### 6.3 第二步：不同主題都熟了才提速

- 換過至少 4 個不同主題（含通識）仍覺得太簡單、表現穩定：教材難度一次跳 2–3 個小階。
- 若會跨大級：主動提供**跳級檢核**（綜合測驗＋評估對話）。
  - 通過：直接升級，不需要等積分達到門檻；積分照常累積。
  - 未通過：等級不變，但教材難度保留在較高的小階繼續練。

## 7. 主題：興趣＋通識

- **興趣主題**：使用者的關鍵字（第 14 節）。
- **通識主題**：工作區的 `topics.toml`，可增減。預設：
  - 生活類：日常生活、校園與社團、飲食、旅行、興趣嗜好、影視音樂與遊戲、運動、人際關係與感情、打工與職涯
  - 社會類：科技與網路、健康、環境、社會議題、文化與歷史、經濟、時事
- **比例**：預設興趣 60%、通識 40%（`profile.toml` 可調）；通識輪流出現，確保每個主題定期碰到。
- **主題熟悉度**：分別記錄每個主題下的單字掌握度與正確率；進度頁顯示哪些主題還弱；跳級機制用它判斷。
- **對話情境**：通識主題對話設定成和國外同齡學生聊天，例如「交換學生第一天」「社團聊天」「討論一則新聞」。

## 8. 積分

### 8.1 主動練習：完成並通過一個單元＝1 分

| 單元 | 通過條件 |
| --- | --- |
| AI 對話 | 完成設定的回合數，且每回合真的有開口（偵測到實際內容，不是空白或一兩個字） |
| 閱讀／聽力測驗 | 一組題目（例如 5 題）正確率達標（預設 70%） |
| 中翻英／中翻日、造句、改寫 | 一組題目正確率達標 |
| 聽寫、跟讀 | 一組句子相似度達標 |
| 複習卡片 | 一輪（例如 20 張）完成 |
| 每日課程結尾測驗 | 正確率達標 |
| 程度檢核、跳級檢核 | 完成（另有升級效果） |

- **未通過＝0 分**，可以重做；錯題照樣進錯題本。
- **高分加成**：正確率 95% 以上，或對話評估「優秀」，額外 +0.5 分（可關閉）。
- **題型可以一直增加**，都照「完成＋通過＝1 分」，不另外調權重。

### 8.2 被動接收：長時間累積

- 單純聽或讀，**每累積 50 分鐘＝1 分**。
- 只計算在 App 內實際播放或閱讀的時間，閒置不算。

### 8.3 不算分的

手動登記、App 以外的任何學習。

### 8.4 分技能累積

每種語言的積分拆成**聽、讀、說、寫、單字文法**，總分為加總。用途：

- 進度頁顯示偏向（作者的英文預期是聽高、說寫低）。
- 每日課程自動多排弱項。
- 升級評估看技能平衡（第 9 節）。

### 8.5 紀錄格式

`records/points/YYYY-MM-DD.csv`：

```csv
time,lang,unit,skill,points,score,detail
2026-11-06T09:12:00+08:00,en,conversation,speaking,1.5,0.96,"conversations/en/2026-11-06-campus.md"
2026-11-06T09:30:00+08:00,ja,quiz,grammar,1,0.80,"lessons/ja/…"
2026-11-06T10:00:00+08:00,en,listening,listening,1,,"50 min"
```

一天一個檔案、只新增不修改，多台電腦同步時不會衝突。資料庫可以從這些檔案重建。

### 9.2 綜合評估

| 條件 | 小階 | 大級 |

## 10. AI 對話

### 10.1 流程

1. AI 依「興趣／通識」比例與主題熟悉度選一個議題，結合使用者程度開場。
2. 使用者講約 **15 秒**（可設定；打字模式則限制長度）。
3. AI **不糾正**：把使用者的意思用更有組織的說法重講一遍（recast），再問下一個問題。
4. 達到回合上限（預設 **20**，可設定 15–20）就顯示完成、結算積分；**這段對話鎖定，不能繼續聊**。回合上限同時限制 context 大小。
5. 結束後的回饋（和對話分開，不打斷流暢感）：
   - 可以說得更好的句子（原句 → 建議）
   - 用到的目標單字、沒用到的目標單字
   - 建議加入生字的字（一鍵加入）
   - 主題關鍵字回饋（第 14 節）
   - 評估：流暢度、目標單字使用、文法（決定通過與高分加成）

### 10.2 兩種語言的 system prompt

放在 `prompts/conversation_en.md`、`prompts/conversation_ja.md`（MiniJinja），可被工作區覆蓋。

- **英文（輸出練習）**：
  - 從單字庫挑 3–5 個「認得但很少主動使用」的字作為本次目標字，透過提問自然地引導使用者用到。
  - 使用者用到目標字就記一次「主動使用」，之後少挑。
  - recast 時示範更精確或更自然的用字。
- **日文（低壓力開口）**：
  - 只用目前小階範圍的文法與單字，句子短。
  - 提供句型開頭（例如「〜が好きです。なぜなら…」）。
  - 可以混中文；AI 用日文重講使用者混中文的部分，示範怎麼說。
  - 使用者可先打字再改用說的；鼓勵、不施壓。

### 10.3 技術

- `LlmProvider` 擴充成多回合（messages）；Claude 訂閱與 API key 都支援（訂閱：每回合把整段對話傳給 `claude -p`）。
- 每回合回覆用 JSON Schema：`{ "recast": "...", "question": "...", "used_targets": [...] }`；結束評估另一個 schema。
- 對話紀錄存 `profiles/<id>/conversations/<lang>/<日期>-<主題>.md`（Markdown＋內嵌資料，與教材相同做法）。

## 11. 每日課程

每天一課，長度依 `daily_minutes`（預設 30 分鐘）：

1. **到期複習**（複習卡片單元）
2. **今日文章**：依配方挑選、改寫到目前難度，含目標單字與文法
3. **測驗**：閱讀理解、填空、中翻英或中翻日（依弱項加權）
4. **跟讀或聽寫**（第 15 節）
5. **一段 AI 對話**（主題延續今日文章或通識輪替）
6. **結束**：難度回饋（前 5 課）、關鍵字回饋、今日積分

提醒用已有的行事曆與信件功能（每日固定時間）。

## 12. 題型

都照「完成＋通過＝1 分」。第一批：

| 題型 | 技能 | 說明 |
| --- | --- | --- |
| 閱讀理解選擇題 | 讀 | 第一版已有 |
| 簡答 | 寫 | 第一版已有（自評＋模型判斷） |
| 填空（克漏字） | 單字文法 | 從今日文章挖空目標字 |
| 中翻英／中翻日 | 寫 | 模型評分並給修改建議 |
| 句型造句 | 寫 | 用指定單字或文法造句 |
| 換句話說 | 寫 | 用更簡單或更正式的方式改寫 |
| 聽力選擇題 | 聽 | 文章或句子朗讀後作答 |
| 聽寫 | 聽＋寫 | 逐字比對 |
| 跟讀 | 說 | 錄音轉文字後比對（近似分數） |
| 對話 | 說 | 第 10 節 |

模型評分的題目（翻譯、造句、改寫）用 JSON Schema 回傳分數與建議。

## 13. 課程配方與教材製作

配方是設定檔（`recipes/*.toml`，個人或共用），可以有好幾套。

### 13.1 興趣配方

```toml
kind = "interest"
name = "AI 與半導體"
lang = "en"
keywords = ["AI chips", "semiconductor"]
sites = []                  # 可選：指定網站
per_week = 3
```

1. **判讀**：關鍵字、網址或照片 → 主題與關鍵字。
2. **搜尋**：從 `sources.toml` 的來源依關鍵字篩選最近新聞；API key 模式可選用 Claude 網路搜尋（另外收費、需使用者開啟）。Google News 類搜尋站使用條款有疑慮，不使用。抓取一律遵守 robots.txt。
3. **難度**：依使用者目前難度改寫。
4. **產生課程**：文章、題目、對話主題。

### 13.2 固定配方

```toml
kind = "fixed"
name = "TOEIC 單字"
lang = "en"
vocab = ["vocab/toeic-en.csv"]
grammar = []
per_day = 10                # 每天帶入幾個新字
```

1. 讀取上傳的單字表或文法句型。
2. 找含有這些字或句型的新聞；找不到就生成短文把它們放進去。
3. 濾掉超出難度的句子。
4. 排成每日課程（第 11 節的「今日文章」與題目）。

### 13.3 照片

- 拍照（或上傳圖片）→ 支援圖片的模型讀出文字與主題（Claude API 支援；Mac 上的 Gemma 4 之後支援）。
- 可直接做成教材，或成為興趣配方的關鍵字。
- 圖片會送到模型；介面上明確標示。原圖存 `profiles/<id>/photos/`（可選不保存）。

## 14. 關鍵字回饋

- 每課、每段對話結束時列出本次關鍵字，可標「有興趣／沒興趣」，或新增關鍵字。
- 存在 `profiles/<id>/interests.csv`：`keyword,lang,weight,updated_at`。
- 權重影響興趣配方與對話選題；長期沒互動的關鍵字慢慢降權。

## 15. 語音

- **語音合成**（朗讀、聽力、聽寫）：先用瀏覽器內建（macOS 有英日語音）；Mac 到貨後換 Kokoro。
- **語音辨識**（對話、跟讀）：先用瀏覽器內建語音辨識。**會把錄音送到 Apple 或 Google 的伺服器**，介面上標示，使用者可以改用打字模式。Mac 到貨後換本機 Whisper，錄音不離開電腦。
- **15 秒錄音**：倒數計時，時間到自動送出；可提前送出。
- **跟讀分數**：錄音轉文字後與原句比對，是**近似的發音分數**，不是逐音素的專業評分；音素級評分之後再研究。

## 16. 家庭成員與學習群組

### 16.1 角色

| 身分 | GitHub | 資料 | Claude |
| --- | --- | --- | --- |
| 擁有者／管理員 | 自己的帳號 | 自己的 private repo | 自己的 |
| 家庭成員 | 不需要 | 管理員 repo 裡的 `profiles/<id>/` | 自己的 |
| 好友 | 自己的帳號 | 自己的 private repo | 自己的 |

**任何人都能當管理員**：用公開程式碼建立自己的工作區與群組即可。一個人可以是自己家庭的管理員，同時是別人群組的成員，也可以加入多個群組。

### 16.2 家庭成員

- **用管理員的電腦**：直接切換使用者。
- **用自己的電腦**（deploy key，不需要 GitHub 帳號）：
  1. 家庭成員的 App 產生 SSH 金鑰，顯示公鑰與 QR code。
  2. 管理員在 App 按「加入家庭成員」，貼上公鑰；App 帶管理員到 repo 的 deploy key 設定頁新增（開啟寫入權限）。這是管理員的一次同意。
  3. 家庭成員的 App 用這把金鑰 pull／push；管理員可隨時在 GitHub 撤銷。
- **限制（介面上說明）**：deploy key 無法限制只讀某個資料夾，家庭成員讀得到整個 repo。

### 16.3 學習群組

```
<群組 repo>/
  group.toml               名稱、管理員、成員、邀請中
  members/<github 帳號>/   等級、積分（分技能）、連續天數、本週練習、最近完成的單元
  members/<github 帳號>.<家庭成員 id>/   由管理員代傳的家庭成員摘要（可選）
  shared/                  想分享的配方或教材（可選）
```

- **建立**：任何人都能「建立學習群組」，建立者是管理員。
- **邀請**：管理員輸入朋友的 GitHub 帳號 → 寫進 `group.toml` → App 帶管理員到 GitHub 協作者邀請頁。真正的權限由 GitHub 控管。
- **加入**：朋友接受邀請後，在 App「加入學習群組」貼上 repo 網址。
- **管理員權限**：邀請、移除（同時提醒到 GitHub 撤銷）、指定其他管理員。
- **代傳家庭成員**：家庭成員沒有 GitHub，可由其管理員的 App 代為上傳摘要；需管理員與該家庭成員都同意，預設關閉。
- **只放摘要**：單字、教材留在各自的私人 repo，除非另外選擇分享到 `shared/`。
- **寫入規則**：App 只寫自己的資料夾；同步時檢查是否有人改了別人的資料夾，有則提醒群組管理員。GitHub 無法強制資料夾權限，這是朋友間的約定，不是安全機制（介面上說明）。
- **好友畫面**：切換群組；成員頭像、等級、積分、技能分布、連續天數、本週練習單元數；本週排行。
- **同步**：兩個按鈕「取得最新」（pull）與「上傳我的進度」（push）；開啟 App 時自動取得。

### 16.4 兩種共用方式

| | 共用一個工作區 | 各自工作區＋學習群組 |
| --- | --- | --- |
| 適合 | 家人、伴侶 | 朋友 |
| 看得到 | 所有檔案（含單字庫） | 只有進度摘要 |
| GitHub | 家庭成員不需要 | 每人自己的帳號 |

## 21. 尚未實測與風險

- **Claude Code 在 macOS 的登入隔離**：`CLAUDE_CONFIG_DIR` 已確認可用，但鑰匙圈中的憑證是否依資料夾分開，需在 Mac 實測。
- **瀏覽器語音辨識**：隱私（送到 Apple／Google）、日文辨識品質、Safari 與 Chrome 差異。
- **跟讀分數**只是近似。
- **門檻數值**是依公開資料的粗估，需要實際使用後校準。
- **deploy key** 無法限制資料夾；**學習群組**的資料夾寫入規則不是強制的。
- **單字表版權**：牛津 CEFR 單字表等由使用者自行匯入，不放進公開 repo。
- **網路搜尋**：Claude 網路搜尋另外收費；新聞網站使用條款各異，教材只供個人學習。
